# Impeccable — RIVET Design Context

## Design Context

### Users
Professional developers and engineering teams who care about code quality, security, and tech debt.
They live in terminals and IDEs. They want dense, scannable information — not marketing fluff.
Context of use: reviewing a scan report, pasting a file for quick analysis, or running the CLI in CI.

### Brand Personality
**Honest. Precise. Forged.**
Feels like a serious tool: calm confidence, industrial warmth (forge/heat), zero gimmicks.
Emotion: trust and clarity — "this will help me ship safer code."

### Aesthetic Direction
- **Visual tone**: Terminal-inspired forge aesthetic. Charcoal surfaces with a single amber accent.
- **References**: Linear (restraint, density, hairlines), Vercel (marketing clarity), Stripe (hierarchy),
  GitHub CLI (terminal craft), Amber Console / terminal UI (forge heat — used lightly, not CRT cosplay).
- **Anti-references**: Purple/cyan AI gradients, aurora blobs, glassmorphism everywhere, glow shadows,
  emoji CTAs, identical icon+card grids, Inter-default SaaS look, sparkle/"powered by AI" badges.
- **Theme**: Dark-first. Warm-tinted neutrals. OKLCH tokens. Sharp radii (2–6px). Flat data surfaces;
  elevation only on overlays (modals).
- **Type**: IBM Plex Sans (UI) + JetBrains Mono (code, metrics, labels).
- **Motion**: Purposeful only — rise-in on hero, border/bg hover, cursor blink in terminal demos.
  Respect `prefers-reduced-motion`.

### Design Principles
1. **One accent** — Amber (`--accent`) for CTAs, focus, and brand marks. Semantic colors for severity only.
2. **Density over decoration** — Hairline borders and surface steps create hierarchy; no decorative cards.
3. **Terminal honesty** — Code and metrics use monospace; CLI demos are first-class UI, not afterthoughts.
4. **Teach, don't dazzle** — Explanations and empty states inform; motion never distracts.
5. **Pass the AI-slop test** — If someone would guess "AI made this," redesign until they wouldn't.
